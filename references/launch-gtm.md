# 发布上市与增长全本

> 本文件为 IdeaToLaunch 内建方法论，独立使用

本文件覆盖：发布前六线就绪评审、四种发布策略的适用与风险、硬件量产爬坡放行判据、GTM 渠道设计、上市内容资产清单、发布后 30/60/90 天运营基线、红线纪律。所有状态声明统一用 VERIFIED / ESTIMATED / ASSUMED / UNVERIFIED 四态；发布策略选择、量产放行、上市声明必须升级给用户，以结构化决策包（推荐 + 理由 + 选项 + 影响 + 证据 + 不确定性）呈现。

## 一、发布前就绪评审（六线清单）

每条给验收标准。**任一线存在"未达标"项，不得宣布"上市"**；允许在标注限制条件后宣布"内测/预售开启"。

### 1.1 产品线

| 检查项 | 验收标准 |
|---|---|
| 核心功能完整 | 价值主张承诺的"必要收益"对应功能 100% 可用，无"敬请期待"占位 |
| 关键缺陷清零 | 阻塞级缺陷 0；严重级缺陷有规避方案且在说明书中明示 |
| 性能基线达标 | 标称参数有实测记录（硬件实测报告/软件压测报告），状态 VERIFIED |
| 版本与回滚 | 发布版本号确定；软件有可回滚方案，硬件有批次追溯编码 |

### 1.2 供应链线（硬件必选；软件改为"基础设施线"）

| 检查项 | 验收标准 |
|---|---|
| 现货/产能 | 首批可交付数量已入库或排产完成，数量为实测而非计划值 |
| 关键物料安全库存 | 长交期物料有第二供应商或 ≥1 个生产批次的库存 |
| 质检规程 | 出厂检验项目清单 + 抽样方案 + 合格判定标准已成文并执行过一次完整试检 |
| 基础设施（软件） | 云服务容量按峰值 3 倍预估压测通过；故障告警与值班机制就位 |

### 1.3 合规线

| 检查项 | 验收标准 |
|---|---|
| 强制认证 | 硬件：销售目标市场的强制认证（如 CCC/CE/FCC）证书在有效期内，证书编号可查（VERIFIED） |
| 资质牌照 | 软件/服务：所需 ICP、行业牌照、支付资质齐备 |
| 隐私与数据 | 隐私政策成文；数据收集项与政策逐条一致；涉及个人信息的完成合规评估 |
| 宣称合规 | 所有功效/性能宣称有对应证据文件，逐条挂台账；无证据的宣称已从物料中删除 |
| 知识产权 | 商标已申请或注册；核心设计/代码的权属链清晰 |

### 1.4 客服线

| 检查项 | 验收标准 |
|---|---|
| 客服通道 | 至少一个实时通道（在线/电话）+ 一个异步通道（邮件/工单），响应时限公开承诺 |
| 知识库 | Top20 预期问题的标准答复成文，客服培训完成 |
| 退换修流程 | 退货、换货、维修各自的操作流程、时限、运费承担规则成文 |
| 升级机制 | 客服无法处理的问题有明确的二线升级路径与 SLA |

### 1.5 内容线

| 检查项 | 验收标准 |
|---|---|
| 上市内容资产 | 第五章清单全部完成并通过事实核查（每个参数可溯源） |
| 视觉与文案一致 | 各渠道页面、包装、说明书参数一致，抽样比对无冲突 |
| 多语言（如适用） | 目标市场语言版本完成母语审校，非机器直译 |

### 1.6 渠道线

| 检查项 | 验收标准 |
|---|---|
| 渠道合同 | 上架/经销协议已签署，结算与扣点条款明确 |
| 库存入仓 | 首批货已到渠道仓或自建仓，系统库存数 = 实盘数 |
| 价格体系 | 各渠道价格表成文，含促销价下限与窜货管理条款 |
| 履约测试 | 完成 ≥1 单全流程测试单（下单→发货→签收→退货演练） |

### 1.7 就绪评审结论输出模板

六线逐线评定后，输出一张结论表，升级给用户：

| 线 | 状态 | 未达标项 | 补齐期限 | 责任人 |
|---|---|---|---|---|
| 产品 | 就绪 / 限制就绪 / 未就绪 | | | |
| 供应链/基础设施 | 就绪 / 限制就绪 / 未就绪 | | | |
| 合规 | 就绪 / 限制就绪 / 未就绪 | | | |
| 客服 | 就绪 / 限制就绪 / 未就绪 | | | |
| 内容 | 就绪 / 限制就绪 / 未就绪 | | | |
| 渠道 | 就绪 / 限制就绪 / 未就绪 | | | |

**评定口径：**
- 就绪 = 该线全部检查项达标（状态 VERIFIED）；
- 限制就绪 = 存在未达标项但有明确补齐计划与期限，且未达标项不涉及合规与安全问题——只允许宣布"内测/预售"；
- 未就绪 = 合规、安全、现货能力任一硬伤——不得对外发布任何上市口径。

评审记录（含各项证据链接与状态标签）写入决策台账，作为后续"谁批的发布"的留痕。

## 二、发布策略

### 2.1 四种策略对比

| 策略 | 适用条件 | 主要风险 | 风险缓解 |
|---|---|---|---|
| 灰度发布 | 软件/服务；有可回滚能力；用户可分组 | 早期用户遇到缺陷影响口碑 | 小流量起步（5%），指标正常再逐批放大；回滚预案演练过 |
| 众筹 | 硬件新品；需要验证需求与回笼资金；有交付能力把握 | 跳票、量产翻车导致信任崩塌 | 交期按 PVT 通过后再承诺；预留缓冲期 ≥30%；进度定期公开 |
| 预售 | 需求不确定、库存有限；想锁定首批用户 | 定金纠纷、等待期流失 | 明示发货时间窗与退款规则；等待期持续提供进度内容 |
| 直发（直接现货开售） | 现货充足、渠道就绪、六线评审全过 | 备货资金占用；需求误判积压 | 首批备货按悲观档需求测算；有清仓预案 |

**选择规则：**硬件首发默认 众筹或预售 优先（验证需求 + 缓解现金流）；软件默认灰度发布。直发仅在现货、合规、售后三证齐备且有历史销售数据支撑时使用。策略选择升级结构化决策包。

### 2.2 硬件首批量产爬坡纪律（EVT/DVT/PVT → 量产）

| 阶段 | 目的 | 放行判据（全部满足才进下一阶段） |
|---|---|---|
| EVT（工程验证） | 验证设计原理可行 | 核心功能全部实现；关键参数实测达到设计目标的 90%+；无"原理上做不到"的遗留问题 |
| DVT（设计验证） | 验证设计可制造、可靠 | 全部可靠性测试通过（跌落/老化/环境，按产品类目定）；DFM 问题清零；BOM 冻结 |
| PVT（生产验证） | 验证产线与良率 | 连续 ≥3 个生产批次良率 ≥ 目标良率（目标值事先成文）；节拍满足产能需求；出厂检验规程完整执行 |
| 量产放行 | 正式放量 | PVT 判据全部 VERIFIED；首件检验合格；变更管理流程生效；决策包经用户批准 |

**爬坡纪律：**
- 首批放量 ≤ 计划月产能的 50%，良率稳定 2 周后再爬坡；
- 任何放行判据未达标，不得以"先卖再说"跳过；如实记录未达标项并重新排期；
- 量产中良率突降超 5 个百分点即触发停线评审。

### 2.3 发布日作战清单（D-Day）

| 时点 | 动作 | 验收 |
|---|---|---|
| D-7 | 全物料终检（页面/说明书/包装参数一致性抽比）；客服全量培训与模拟问答；渠道库存复盘 | 抽比无冲突；模拟问答正确率 ≥95% |
| D-3 | 软件发布包冻结 / 硬件首批封存质检；回滚与应急预案演练；发布公告定稿（过证据门） | 演练记录留痕；公告每条宣称挂证据 |
| D-1 | 全链路彩排：下单→支付→履约→售后全流程测试单；值班表确认 | 测试单全流程无卡点 |
| D-Day | 按策略放量（灰度先 5%）；实时监控面板就位（订单、报错、库存、工单）；每小时简报 | 异常触发即按预案处置，处置留痕 |
| D+1 | 首日复盘：指标 vs 预期、异常清单、舆情反馈分类 | 复盘记录写入决策台账 |

## 三、GTM 渠道设计

### 3.1 渠道选择矩阵

| 渠道 | 成本结构 | 控制力 | 适配产品 |
|---|---|---|---|
| 自建（官网/直营店/自有 App） | 固定投入高，单件扣点低 | 最高（价格、数据、体验全控） | 高毛利、强品牌诉求、需要用户数据 |
| 平台（电商/应用商店/外卖平台） | 扣点 5%–30%，流量费另计 | 低（规则受制于平台） | 标准化产品、需要快速起量 |
| 分销（代理/经销） | 让渡毛利 20%–35% | 中（价盘需管理） | 线下依赖强的硬件、区域覆盖需求 |
| 直销（销售团队/顾问式） | 人力成本高，周期长 | 高 | 高客单价、需方案化交付的 B 端 |

### 3.2 客单价 × 毛利匹配渠道规则（经验参考，非定律）

- 客单价 <200 元 且毛利 <50%：只能走平台或自建轻渠道，撑不起分销与直销人力；
- 客单价 200–2000 元：平台 + 自建为主，分销可作为补充；直销不经济；
- 客单价 2000–20000 元：自建/直销可行，分销需要给足毛利空间；
- 客单价 >20000 元（B 端/高端硬件）：直销为主，渠道仅作线索来源；
- 任一渠道的单位经济必须单独测算（渠道 CAC + 扣点后毛利仍为正），算不平的渠道不进入首发。

### 3.3 首发定价与首发权益设计

1. 首发价以商业模式文档（business-model.md）三档测算的基准档为锚，促销折扣必须重算毛利；
2. 首发权益给"时间权益"不给"价格击穿"：优先发货、延保、赠品、创始用户标识优先；直降幅度 ≤15%（经验参考），避免透支后续价盘；
3. 众筹/预售早鸟档设置数量上限，售罄即止，不加档——加档等于变相降价且失信；
4. 明示首发价与后续常态价的关系（"首发特惠，常态价 X"），不得用虚假划线价；
5. 价格体系成文：各渠道价、促销价下限、窜货罚则，渠道签约前发给对方确认。

### 3.4 渠道试投与放量规程

1. **试投：**每个候选渠道先跑 7–14 天小规模试投（预算上限事先成文），记录：曝光→点击→转化→实收→退款全链路数据；
2. **算账：**按试投数据算单渠道 CAC 与扣点后毛利，与商业模式文档基准档对照；偏差 >50% 的渠道降级为观察渠道；
3. **放量：**仅对算得平的渠道放量，放量节奏每周 ≤2 倍，避免流量质量塌陷误判；
4. **价盘巡检：**放量后每周巡检各渠道实际成交价，发现破价/窜货按合同条款处置并留痕；
5. **渠道集中度红线：**单一渠道收入占比 >60% 时启动第二渠道建设（经验参考，非定律），避免平台规则变动一击致命。

## 四、上市内容资产清单

| 资产 | 内容要点 | 验收 |
|---|---|---|
| 产品页 | 一句话价值主张 → 三大核心收益（对接痛点）→ 参数规格表 → 使用场景 → 对比现状 → 价格与权益 → 售后承诺 → 真实 FAQ | 每个参数可溯源到测试报告；无证据的宣称已删除 |
| 说明书 | 开箱清单、安装/激活步骤（图文分步）、安全警示（法规要求的强制项）、故障自查表、保养与寿命说明、合规标识 | 找 3 个未接触过产品的人按说明书独立完成开箱到使用，全程无求助 |
| FAQ | 覆盖购买（价格/发货/发票）、使用（Top20 问题）、售后（退换修政策与时限）三段；与客服知识库同源 | 与客服知识库逐条比对一致 |
| 评测样机政策 | 借测/送测规则、数量上限、是否要求内容审核（只能要求事实纠错，不得要求结论改好评）、披露要求 | 政策成文；评测中出现的"合作/样机提供"必须按平台规则披露 |
| 售后政策 | 保修范围与期限（不低于法定下限）、退换条件与时限、维修流程与预计周期、人为损坏界定、运费承担 | 与法务/合规确认；页面公示版本与合同版本一致 |

## 五、增长与运营基线

### 5.1 发布后 30/60/90 天看什么

| 时点 | 核心指标 | 判读规则 |
|---|---|---|
| 30 天 | 激活率（注册→完成关键动作）；首批退货率；客服工单 Top 问题；渠道转化率 | 激活率 <40%（经验参考）说明上手环节有问题；退货原因分类（质量/预期差/物流）指导修复优先级 |
| 60 天 | 留存率（次月留存，软件）/ 复购与配件购买（硬件）；NPS 首轮；实际 CAC vs 测算 | 实际 CAC 与基准档偏差 >50% 触发单位经济重算；NPS 样本 <30 只作定性参考 |
| 90 天 | LTV 初步实测；回本进度；流失/退货归因；三档测算回写 | 用 90 天实测回写假设台账，更新 LTV/CAC 三档；偏差最大的假设列入下季度实验计划 |

### 5.2 数据不足时的诚实呈现

- 样本量 <30 的指标只呈现原始数字 + "样本不足，不作趋势判断"；
- 留存/LTV 需要长周期数据，未到期时标注"数据不足，预计 {日期} 可初判"；
- 不得用环比/同比美化基数极小的数字（"增长 300%（从 1 单到 4 单）"必须带绝对数）；
- 指标状态随报表呈现：实测为 VERIFIED，含推算成分标 ESTIMATED。

### 5.3 迭代反馈回流机制

1. 每周汇总：客服工单 Top 问题、退货归因、评测/评论中的事实性反馈；
2. 分类处置：缺陷类 → 产品基线变更流程；预期差类（宣传过度）→ 内容资产修正；新需求类 → 假设台账新增，排入验证队列；
3. 任何影响产品定义、BOM、宣称的变更，回写产品基线并传播到所有依赖产物（说明书、页面、包装），受影响产物标"待更新"；
4. 重大反馈（安全问题、系统性缺陷、宣称失实）立即触发决策日志记录 + 用户升级，处理过程全程留痕；
5. 每月将关键指标与当初预测对照结算，更新命中率台账——发布后的复盘与发布前的预测是同一本账。

## 六、升级决策的时刻

以下情形必须升级给用户，以结构化决策包呈现（推荐 + 理由 + 2–4 个选项 + 影响 + 证据 + 不确定性 + 未回复时的继续项）：

- 发布策略选择（灰度/众筹/预售/直发）与首发定价确认；
- 就绪评审存在"限制就绪/未就绪"线，用户仍要推进发布（必须显式记录用户知情决定与限制条件）；
- EVT/DVT/PVT 任一放行判据未达标，涉及跳级放行；
- 实际 CAC 或退货率显著劣于悲观档，需要决定继续投放还是停投整改；
- 触发红线事件后的处置方案。

## 七、红线（不可违反）

1. **不得虚构销量与评价。** 不得刷单、刷评、伪造用户证言、伪造售罄截图；不得把意向、加购、咨询数字包装成"销量"。
2. **上市声明证据门。** 宣布"上市/现货发售"前必须三证齐备：现货能力（库存实盘数，VERIFIED）、合规文件（认证与资质，VERIFIED）、售后能力（客服通道与退换修流程已演练）。任一缺失只能宣布"预售/内测/众筹"，且明示限制条件。
3. **宣称必须有据。** 性能、功效、销量排名、奖项类宣称逐条挂证据；无证据的宣称从所有物料删除，不得"先写上再说"。
4. **价格诚信。** 不得虚构划线价、不得先涨后降伪促销；首发权益规则一经公布不得单方面变更。
5. **数据诚实。** 对外与对内的经营数字同源；对用户的升级决策包中，坏消息不得弱化——证据不足的标 UNVERIFIED，不许包装成乐观预期。
6. **违规处置。** 发现任一红线已被触碰（含历史物料），立即下架相关内容、记录更正日志、向用户升级，不得掩盖后继续。
