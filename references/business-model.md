# 商业模式与定价全本

> 本文件为 IdeaToLaunch 内建方法论，独立使用

本文件覆盖：商业模式设计（价值主张画布 + 商业模式画布）、定价方法论（三法定价 + 价格敏感度测试 + 硬件/软件两条定价线）、单位经济模型（硬件与软件双口径）、财务测算纪律、标准输出物模板。所有数字必须挂假设编号，所有证据必须标注四态（VERIFIED / ESTIMATED / ASSUMED / UNVERIFIED）；涉及定价与商业模式方向性选择时，升级给用户以结构化决策包（推荐 + 理由 + 选项 + 影响 + 证据 + 不确定性）。

## 一、商业模式设计

### 1.1 价值主张画布执行规程

价值主张画布分左右两半，**右半（客户侧）先行**，左半（产品侧）必须逐条对接右半，不得凭空写功能。

**右半：客户侧三栏**

| 栏位 | 填什么 | 怎么收集 | 合格标准 |
|---|---|---|---|
| 客户任务 | 客户试图完成的事：功能任务/社交任务/情感任务 | 访谈 10+ 目标用户、观察真实使用场景 | 至少 3 条任务，按重要性排序 |
| 痛点 | 完成任务时的障碍、风险、坏结果 | 访谈中的抱怨、现有方案的差评与退货原因 | 每条痛点标注强度（高/中/低）与状态标签 |
| 收益点 | 客户期待的结果与意外惊喜 | 访谈中"要是能……就好了"类表述 | 区分"必要收益"与"惊喜收益" |

**左半：产品侧三栏（与右半一一对接）**

| 栏位 | 填什么 | 对接规则 |
|---|---|---|
| 产品功能 | 具体交付物（硬件单品/软件模块/服务项） | 每个功能必须能指出它服务右半哪条任务，找不到对接的功能列入"待砍" |
| 止痛点 | 该功能如何消除哪条痛点 | 每条高强度痛点至少有一个止痛方案，没有方案的痛点标注"未解决" |
| 增益点 | 该功能如何兑现哪条收益 | 必要收益必须 100% 覆盖，惊喜收益允许空缺 |

**执行步骤：**
1. 先填右半：从访谈/观察记录摘录，每条注明来源与状态标签；
2. 再填左半：逐条功能对照，做对接映射表（功能 ID → 任务/痛点/收益 ID）；
3. 计算对接率：左半功能中有右半对接的占比，<80% 说明产品定位漂移，需升级决策；
4. 把"高强度痛点 × 未解决"的组合列入风险清单，作为最小实验候选。

### 1.2 商业模式画布九宫格执行版

每格给出"填什么"与"怎么验证"，填写顺序建议：客户细分 → 价值主张 → 渠道 → 客户关系 → 收入流 → 关键资源 → 关键活动 → 关键伙伴 → 成本结构。

| 格位 | 填什么 | 怎么验证 |
|---|---|---|
| 客户细分 | 最先服务的一个细分人群（人口属性 + 场景 + 付费能力），明确"不服务谁" | 访谈该人群 ≥10 人；确认他们彼此可互相替代（同一人画像） |
| 价值主张 | 一句话：为谁、解决什么、凭什么比现状好 | 向 5 个非目标用户复述，能正确转述 ≥4 人算通过 |
| 渠道 | 触达与交付路径（线上/线下/直销/分销） | 算清单渠道 CAC 与转化率（见第三章），跑 1 个渠道小规模试投 |
| 客户关系 | 获取/留存/增购机制（自助/社群/专属服务） | 试运行一轮留存动作，看 30 天留存是否 ≥ 预期 |
| 收入流 | 收费对象、收费名目、收费时点（一次性/订阅/抽成） | 预售或意向金测试：真实掏钱才算 VERIFIED |
| 关键资源 | 缺一不可的资产（专利/产线/数据/牌照/团队） | 列出资源获取路径与周期；无路径的资源标 UNVERIFIED |
| 关键活动 | 每周必须做对的事（研发/内容/供应链/运营） | 核对活动与价值主张的因果链，断链的活动降级 |
| 关键伙伴 | 供应商/平台/渠道/认证机构 | 至少 1 家进入实质接触（报价/合同谈判），空口意向标 ASSUMED |
| 成本结构 | 固定成本 + 变动成本清单，挂到单位经济表 | 变动成本逐项有报价或实测，不允许"约 X%" |

**铁律：**九宫格里任何一格为空白或全部为 UNVERIFIED 时，不得输出"商业模式已确定"的结论，只能输出"商业模式草案 + 待验证清单"。

## 二、定价方法论

### 2.1 三法定价对比与适用条件

| 方法 | 核心逻辑 | 适用条件 | 局限 |
|---|---|---|---|
| 成本加成 | 成本 × (1 + 加成率) | 成本可测、有明确渠道结构（硬件首发常用作底价锚） | 无视客户支付意愿，容易定低或定高 |
| 竞争参照 | 对标竞品价格 ± 定位差 | 竞品密集、价格透明、替代品成熟 | 陷入价格战；差异化产品无可比对象 |
| 价值定价 | 按客户感知价值/省下的钱定价 | 可量化客户收益（省时/省钱/增收）、差异化明显 | 需要客户访谈与实验支撑，前期成本高 |

**选择规则：**硬件新品以成本加成为底价、竞争参照为天花板、价值定价为目标价，三者交叉出价格区间；软件/服务以价值定价为主、竞争参照校准。最终定价必须从区间升级为具体档位，并升级结构化决策包给用户拍板。

### 2.2 成本加成法操作步骤

1. 列出全部单位成本：BOM（硬件）/云资源与人力分摊（软件）+ 包装 + 物流 + 渠道佣金 + 售后准备金；
2. 确定加成率：硬件按 2.6 节加成链逐层算，软件按目标毛利率倒推；
3. 得出底价 = 单位全成本 ÷ (1 − 目标毛利率)；
4. 标注状态：有正式报价的成本项标 ESTIMATED，供应商口头价标 ASSUMED，无报价标 UNVERIFIED。

### 2.3 竞争参照法操作步骤

1. 选 3–5 个直接竞品 + 2 个替代方案（含"什么都不做"）；
2. 建对比表：价格、核心参数、目标人群、渠道、促销常态价（用常态价而非标价）；
3. 定位价差：明确我们比竞品强在哪/弱在哪，每条差异折算 ±X% 价格容忍度（标注 ASSUMED）；
4. 输出参照区间 = 竞品常态价 × (1 + 净差异容忍度)。

### 2.4 价值定价法操作步骤

1. 量化客户收益：访谈中问"现状方案每月花你多少钱/时间/损失"，记录数值分布；
2. 计算可感知价值 = 现状成本 − 使用我方后成本 + 新增收益；
3. 定价取可感知价值的 20%–40%（经验参考，非定律），客户保留大头收益才有采用动力；
4. 用 2.5 节价格测试验证，未验证前标 ASSUMED。

### 2.5 Van Westendorp 价格敏感度测试（简化版执行规程）

**样本：**目标人群 ≥30 人（低于 30 人只做定性参考，结果标 ESTIMATED 并注明样本量）。

**四个问题（按序询问，单位精确到元）：**
1. 这个价格低到让你觉得"质量肯定有问题"是多少？（太便宜）
2. 什么价格让你觉得"划算"？（便宜）
3. 什么价格让你觉得"贵但还能接受"？（贵）
4. 高到"完全不会考虑"是多少？（太贵）

**分析步骤：**
1. 四组答案各自排序，画累计分布（太便宜/便宜用反向累计，贵/太贵用正向累计）；
2. 找四个交点：太便宜∩贵 = 可接受价格下限；太贵∩便宜 = 可接受价格上限；"太便宜∩太贵"与"便宜∩贵"两交点之间为可接受价格带，其中心为最优参考价；
3. 输出：最优参考价 + 可接受价格带 [下限, 上限]，与 2.2 成本底价对照——下限低于成本底价的，商业模式不成立，升级决策；
4. 记录：样本量、招募渠道、执行日期，写入假设台账。

### 2.6 硬件：BOM 到零售价的上游加成规则

逐层加成，每层给出经验参考区间（非定律，须按项目实际校准）：

| 层级 | 计算 | 经验参考 | 说明 |
|---|---|---|---|
| 出厂成本 | BOM + 组装测试 + 包装 + 损耗 | 损耗率 2%–5% | 量产爬坡期取上限 |
| 售后准备金 | 出厂成本 × 计提率 | 3%–8% | 含保修、退换、备件；高复杂度产品取上限 |
| 含税出厂价 | (出厂成本 + 售后准备金) ÷ (1 − 税率口径调整) | 按适用增值税口径 | 具体税率以财务确认为准 |
| 渠道加价 | 含税出厂价 ÷ (1 − 渠道毛利率) | 电商平台扣点 5%–15%；线下分销 20%–35% | 多级分销逐层复算 |
| 建议零售价 | 渠道加价 + 物流 + 营销分摊 | 物流按件实测；营销按 CAC 预算 | 最终价必须 ≥ 此值才保本 |

**操作纪律：**
- 最终零售价 ÷ BOM 的倍率（常见硬件 2.5×–5×，经验参考）只做 sanity check，不作定价依据；
- 每层加成都挂假设编号，供应商报价标 ESTIMATED，无报价项标 UNVERIFIED；
- 首发促销价必须另行测算毛利，不得直接沿用零售价口径。

### 2.7 软件订阅：定价档位设计原则

1. **档位数量：**2–4 档（含免费档时总档数 ≤4），超过 4 档显著增加选择困难；
2. **档位锚点：**按"客户任务规模"分档（用量/席位/项目数），不按功能堆砌分档；核心止痛功能必须在最低付费档可用，否则免费用户无法验证价值；
3. **中档为主推：**默认高亮中档，目标 ≥60% 付费用户落在中档；高档用于锚定与封顶；
4. **年付折扣：**年付 = 月付 × 10（即 2 个月折扣，经验参考），年付占比目标 ≥30%（经验参考）；
5. **免费档红线：**免费档的单位服务成本必须显式测算；免费→付费转化率假设没有本项目数据时标 ASSUMED，行业参考 2%–5%（ESTIMATED，仅作先验）；
6. **涨价机制：**首版定价文档中预留"功能扩展后重新定价"条款，避免历史价格锁死。

## 三、单位经济模型

### 3.1 计算口径与公式

**通用公式：**

| 指标 | 精确公式 | 取数来源 |
|---|---|---|
| CAC | 周期内全部销售与营销费用 ÷ 同期新增付费客户数 | 费用取财务实账（含人力分摊），客户数取订单系统；口径必须为"付费客户"而非注册/线索 |
| 客单价 ARPU | 周期收入 ÷ 付费客户数 | 收入取实收（扣除退款） |
| 毛利率 | (收入 − 变动成本) ÷ 收入 | 变动成本含交付、云资源、渠道扣点、售后，不含固定研发 |
| LTV（软件） | 月 ARPU × 毛利率 × 客户平均生命周期（月）；生命周期 = 1 ÷ 月流失率 | 流失率取近 3 个月滚动实测；无实测标 ASSUMED |
| LTV（硬件） | (单台毛利) + 复购/配件/服务收入 × 毛利率 | 单台毛利 = 零售价 − 单位全成本（见 2.6）；复购率无实测标 ASSUMED |
| 回本期 | CAC ÷ (月 ARPU × 毛利率)（软件）；CAC ÷ 单台毛利（硬件，单位：台数） | 软件单位为月；硬件输出"卖多少台回本" |
| 月烧钱率 | 固定成本 + 变动成本 − 收入 | 财务实账，按月更新 |

### 3.2 健康参考线（经验参考，非定律）

| 指标 | 参考线 | 适用 | 说明 |
|---|---|---|---|
| LTV / CAC | ≥3 | 软件为主 | <1 明确不成立；1–3 需看增长阶段 |
| 回本期 | ≤12 个月（软件）；首批量产批次内回本（硬件） | 通用 | 硬件必须算"单批次盈亏平衡台数" |
| 毛利率 | 软件 ≥70%；硬件 ≥40%（消费级）/ ≥25%（重渠道硬件） | 通用 | 低于参考线需说明结构性原因 |
| 月流失率 | ≤3%（SMB 订阅）；≤1%（企业级） | 软件 | 上线初期样本不足时不得宣称达标 |
| 退货率 | ≤ 行业类目中位数 | 硬件 | 类目中位数取平台公开数据，标 ESTIMATED |

**纪律：**以上均为经验参考，不是定律。引用时必须注明"经验参考"；本项目实测数据一旦产生，以实测为准并回写台账。

## 四、财务测算纪律

1. **假设编号制：**每个测算数字必须挂到假设台账编号（如 A-03）；台账每条假设记录：内容、数值、状态标签（VERIFIED/ESTIMATED/ASSUMED/UNVERIFIED）、来源、最后复核日期；
2. **三档测算：**任何收入/成本/回本预测必须同时给出乐观/基准/悲观三档，档位差异由具体假设驱动（如转化率 2%/4%/8%），不允许整体拍 ±X%；
3. **禁止单点精确数字：**不得输出"预计第一年收入 3,472,150 元"这类伪精确数字；正确形式为"基准档约 350 万，区间 [悲观 120 万, 乐观 680 万]，关键驱动假设 A-03（转化率）当前状态 ASSUMED"；
4. **敏感性排序：**列出对结果影响最大的前 3 个假设，作为最小实验优先验证对象；
5. **回写机制：**实测数据产生后 7 天内回写假设台账与三档测算，旧版本保留留痕，不得覆盖。

## 六、升级决策的时刻

以下情形必须升级给用户，以结构化决策包呈现（推荐 + 理由 + 2–4 个选项 + 影响 + 证据 + 不确定性 + 未回复时的继续项）：

- 最终定价档位确认（影响毛利与定位，不可逆性强）；
- 可接受价格带下限低于成本底价（商业模式不成立的判定）；
- 收入流模式分叉（买断 vs 订阅 vs 抽成）；
- LTV/CAC 基准档 <1 且用户仍要推进（必须显式记录用户知情决定）。
