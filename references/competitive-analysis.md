# 竞品分析全本

> 本文件为 IdeaToLaunch 内建方法论，独立使用。

本文档规定竞品识别、对比分析、差异化定位与动态跟踪的完整规程。你（AI 主管）在想法验证期与立项前按本文件执行；产出直接服务于"该不该做"的决策验证，所有结论按四态标注证据等级：**VERIFIED / ESTIMATED / ASSUMED / UNVERIFIED**（定义见 decision-quality.md 第二节）。

---

## 一、竞品识别：三类竞品都要找全

### 1.1 三类竞品定义与识别方法

| 类型 | 定义 | 识别方法 | 示例（以"AI 面试教练"为例） |
|---|---|---|---|
| 直接竞品 | 同一需求、同类方案 | 应用商店搜核心关键词、行业报告竞品章节、问用户"你还用过/听说过什么" | 其他 AI 模拟面试产品 |
| 间接竞品 | 同一需求、不同形态方案 | 问用户"除了这类产品你还怎么解决"、搜索替代品类关键词 | 真人面试辅导、面试培训班、求职陪跑服务 |
| 替代方案（用户现状土办法） | 用户现在不花钱或低成本凑合的方式 | 访谈中问"你现在具体怎么做的"，追到最细 | 自己对着镜子练、让朋友模拟、刷面经帖、干脆不准备 |

**硬性规则**：
- **"用户现状土办法"必须进竞品清单**——它是用户真正的默认选项，你的产品首先要打败的是"继续凑合"；
- 每类至少识别 2 个，找不到间接竞品和土办法说明你还没做用户访谈，回到 market-research.md 第三节；
- "我们没有竞品"不是结论，是危险信号：要么市场不存在，要么你没找。两种情况都必须如实呈现。

### 1.2 竞品清单登记表

| 竞品名 | 类型 | 一句话描述 | 目标客群 | 定价 | 信息来源 | 采集日期 |
|---|---|---|---|---|---|---|
| 例：Product X | 直接 | AI 模拟面试 SaaS | 应届生 | ¥68/月 | 官网定价页 + App Store 页面 | 2024-XX-XX |

## 二、分析框架

### 2.1 功能对比矩阵

**步骤**：
1. 列出用户完成任务所需的全部关键功能维度（从用户访谈提炼，不是从竞品官网抄卖点）；
2. 行 = 功能维度，列 = 各竞品 + 用户土办法 + 你的方案；
3. 每格填：有 / 无 / 部分有，并在括号内注明依据（亲测 / 官网声称 / 用户评价）；
4. 亲自试用直接竞品（注册、走核心流程），官网声称与亲测不符时以亲测为准并记录差异。

**模板**：

| 功能维度 | 竞品A | 竞品B | 用户土办法 | 我们的方案 |
|---|---|---|---|---|
| 核心场景覆盖 | 有（亲测） | 部分（官网声称） | 无 | 计划有 |
| 关键差异化点 X | 无 | 有（差评中确认可用） | 无 | 计划有 |
| 上手成本 | 高（注册需企业认证） | 低 | 零 | 低 |

### 2.2 定价对比

- 记录：定价模式（订阅/买断/按量/免费+增值）、各档价格、免费额度、企业版报价方式；
- 同时记录**用户实际付了什么**：访谈中问出的现有支出（含土办法的隐性成本：时间、人情）；
- 定价信息必须带采集日期——竞品调价频繁，超过 6 个月的定价数据标注"时效存疑"；
- 结论输出：市场价格带（下限-主流-上限）+ 你的定价在这个带里的位置及理由。

### 2.3 用户评价挖掘：差评是金矿

**采集渠道**：App Store / 应用商店评论、知乎/小红书吐槽帖、黑猫投诉、垂直社区、招聘网站上竞品员工的离职评价（侧面看内部问题）。

**规程**：
1. 每个直接竞品至少读 50 条差评/中评（按"最有用"和"最新"各取一半）；
2. 逐条归类到问题桶：功能缺失 / 质量缺陷 / 价格不满 / 服务问题 / 弃用原因；
3. 记录高频问题（出现 ≥3 次）为"竞品结构性弱点"，这些是差异化机会；
4. 好评也要读，但只看"用户因为什么留下来"——那是竞品的护城河，你必须有应对；
5. 区分"个别吐槽"与"系统性抱怨"：只有高频出现的才升级为结论，单次出现的记为线索。

**差评挖掘记录表**：

| 竞品 | 问题桶 | 原话摘录 | 出现频次 | 是否系统性 | 对我们的启示 |
|---|---|---|---|---|---|
| 竞品A | 弃用原因 | "用了两周发现题目不更新" | 7 次 | 是 | 内容更新频率是留存关键 |

### 2.4 供应链 / 成本结构推断

目的：判断竞品的成本底线与价格战能力。规程：

1. **团队规模**：招聘网站在招岗位数与类型、LinkedIn/脉脉公司页人数 → 推断月人力成本；
2. **技术路线**：招聘信息中的技术栈要求、专利/论文、产品更新频率 → 推断自研 vs 套壳；
3. **资金状况**：融资轮次与金额（企查查/天眼查/IT桔子）→ 推断烧钱能力；
4. **成本大头**：从商业模式推断（如重线下交付的竞品，规模化慢；纯 API 套壳的竞品，毛利受制于上游模型定价）；
5. 输出：竞品成本结构画像（固定成本/变动成本大头各是什么）+ "它能不能打价格战、能烧多久"的判断。

**注意**：本节全是推断，整体最高记 ASSUMED，每条必须写明推断依据；不得把推断写成事实。

## 三、差异化定位与可防御性评估

### 3.1 差异化陈述格式

```
当【目标用户】要【完成什么任务】时，
与【最强竞品/土办法】相比，
我们在【哪个维度】上【具体好多少/不同在哪】，
证据是【什么】（证据等级）。
```

写不出"具体好多少"的差异化不是差异化，是口号。

### 3.2 可防御性五维评估

对每个声称的差异化，逐维打分（强/中/弱 + 依据）：

| 防御维度 | 评估问题 | 强的标志 |
|---|---|---|
| 技术 | 竞品复制这个能力要多久？ | 需要长期积累的数据/算法/工程，非 3 个月可追平 |
| 成本 | 我们能否在同等质量下持续更便宜？ | 结构性成本优势（渠道、规模、自动化），非补贴堆出来的 |
| 网络效应 | 用户越多价值越大吗？ | 每新增用户提升其他用户体验（数据飞轮、双边市场） |
| 切换成本 | 用户来了之后走得掉吗？ | 数据沉淀、工作流嵌入、关系链在产品里 |
| 品牌 | 用户认的是不是"我们"？ | 品类心智占位、口碑复利 |

**评分规则**：五维全弱 = 差异化不可防御，必须在结论中如实写明；有三维以上中/强才可作为"做"的支撑依据之一。

### 3.3 "没有差异化"是合法结论

- 分析后如实得出"没有可防御的差异化"，**必须直接说出来**，并给出三条路径供决策：(a) 换细分人群/场景重做定位；(b) 接受低差异化但比拼执行与成本（须说明凭什么赢）；(c) NO-GO；
- 禁止编造"我们更懂用户""我们体验更好"这类无证据的差异化话术；
- 该结论按第四态流程呈现：差异化证据为 ASSUMED/UNVERIFIED 时，结论必须带标签，不得写成既定事实。

## 四、竞品动态跟踪

### 4.1 更新触发条件（满足任一即触发重分析）

- 直接竞品发布重大版本/进入新品类/宣布融资；
- 直接竞品调价或改变商业模式；
- 出现新进入者（尤其大厂下场）；
- 竞品关停、被收购、核心团队离职潮——这是市场信号，同样要记录分析；
- 无事件时，每 3 个月常规复查一次清单上的直接竞品。

### 4.2 跟踪记录格式

```
【竞品动态记录】
日期：
竞品：
事件：（事实描述，附来源链接）
来源与可信度：官方公告 / 媒体报道 / 用户反馈 / 传言（传言不得入结论）
对我们的影响：威胁升级 / 威胁下降 / 无实质影响
需要动作：无需动作 / 更新对比矩阵 / 触发差异化重评估 / 升级给决策层
```

```
【竞品分析结论卡】
结论：（一句话，如"在 X 细分场景存在可防御的差异化：______"或"未找到可防御差异化"）

证据等级：VERIFIED / ESTIMATED / ASSUMED / UNVERIFIED

最大软肋：本结论最可能被什么推翻
```

## 六、红线

1. **竞品数据必须标注来源与时间**：无来源、无日期的竞品信息不得进入任何结论；超过 6 个月未更新的定价/功能信息必须复查后才能引用；
2. **不得低估竞品**：禁止"他们做不出来""大厂看不上这块""他们体验很差"式臆断——没有证据默认竞品能做好；评估竞品能力时以其已展示的最强表现为准；
3. **官网话术不是事实**：竞品自称的能力记 UNVERIFIED，亲测或多源用户评价确认后才升级；
4. **成本结构推断必须标 ASSUMED**：推断链写全，不得呈现为已知事实；
5. **"没有竞品"与"没有差异化"都必须如实呈现**，不得为了促成 GO 而淡化。
