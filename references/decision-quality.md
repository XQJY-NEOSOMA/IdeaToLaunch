# 决策质量方法论全本

> 本文件为 IdeaToLaunch 内建方法论，独立使用。

## 一、判断合同（五段式）+ 推理叙事

每次决策评估的产出物（模板：`templates/judgment-contract.md`）。面向用户的呈现必须包含**一段话结论**与**推理叙事**（候选结论、关键证据、分歧假设、取舍理由、被否决项、最大不确定处——见 SKILL.md「呈现层契约」）；存档部分为五段判断合同，五段缺一不可：

1. **当前判断**——建议怎么做（或诚实地说：先别决定）；
2. **为什么**——依据是什么（每条依据可追溯到具体证据或假设编号）；
3. **最大未知**——哪件事最可能让判断失误；
4. **下一步**——建议先做的小实验/行动；
5. **什么会改变判断**——发生什么情况就该改主意（翻转条件：哪个关键信念变化多少会翻转结论）。

呈现时五段完整，不许合并省略第五段——那是用户最值钱的一段。

## 二、假设清单与状态标签

把想法里"默认相信的事"全部显性化，每条标注：

| 状态 | 含义 | 使用规则 |
|---|---|---|
| VERIFIED | 本项目内已验证（实验/付费/直接观察） | 可当事实用 |
| ESTIMATED | 有外部证据但未在本项目验证 | 可用，呈现时必须带标签 |
| ASSUMED | 工程/经验假设 | 可用，必须列入跟踪 |
| UNVERIFIED | 未验证的关键命题 | 不得作为决策依据；必须先验证 |

### 两套标签体系的分工与映射（2026-08-24 治理，R1 遗留问题）

本体系存在两套标签，**服务对象不同，禁止混用**：

| | 四态（假设标签） | 八态（事实/参数标签） |
|---|---|---|
| 回答的问题 | 这个说法被证实了没？ | 这个数值是从哪来的？ |
| 适用对象 | 假设、命题、判断（research_log 假设台账、handoff key_assumptions、判断合同） | 参数、数值、规格（product_baseline 关键参数表） |
| 枚举 | VERIFIED / ESTIMATED / ASSUMED / UNVERIFIED | V实测 / S仿真 / C计算 / E外部证据 / A假设 / P待供应商 / T待测试 / R废弃 |

**映射规则**（八态参数升级为四态假设时的对应）：

| 八态 | → 四态 | 说明 |
|---|---|---|
| V 实测 | VERIFIED | 本项目内直接观测 |
| S 仿真 / C 计算 | ESTIMATED | 本项目产出但非现实直接观测 |
| E 外部证据 | ESTIMATED | 外部证据未在本项目验证 |
| A 假设 | ASSUMED | 工程性假设 |
| P 待供应商 / T 待测试 | UNVERIFIED | 待外部回填，不得作决策依据 |
| R 废弃 | —（不再作为依据） | 台账留痕，不进新结论 |

**编号声明**：〔R-xx〕是研究结论卡编号，与八态中的 R（废弃）无关，属不同体系——该说明必须出现在任何同时使用两处的文档图例中。product_baseline 的"假设跟踪"表一律使用四态（与 pipeline 机械解析口径一致）。

## 三、证据权威分级（结构性，不可打分抹平）

从低到高：
1. 模型先验 / 常识推断
2. 外部二手研究（行业报告、竞品信息）
3. 经过审读的外部研究
4. 创始人/用户陈述（报告性信息）
5. 本项目内实验结果
6. 客户真实承诺/付费（最接近本项目现实）

**铁律：外部研究不能自动变成本项目事实。**"行业报告说 80% 客户愿意付" ≠ "本项目的客户会付"。要获得最高权威，必须有本项目内的直接观察、实验或支付行为。公司案例只能作可迁移先验，且迁移力度要单独评估。

## 四、ABSTAIN 纪律（暂不决策是一等输出）

触发条件：关键不确定性超过可承受阈值，或证据相互冲突未解。

输出必须附带：
- 还需要什么证据，或
- 一个**最小实验**：成本最低、周期最短、有明确验证标准（什么结果算证实/证伪）。

呈现 ABSTAIN 时不得美化措辞让它看起来像 GO。

## 五、预测登记与结算（账本纪律）

1. **先登记**：每个可检验预测写下——预测内容、概率（0-1）、到期时间/判据、当时依据。使用 `templates/decision-journal.md`。
   - **登记概率是未经校准的先验**，它记录"你当时怎么想"，不是"你有多准"。呈现时必须与校准状态并列（如"0.65，未校准"），避免读者把先验概率误读为校准后置信度；判断合同模板中的"置信度"栏同理——样本不足一律写"未校准"。
2. **后结算**：到期后逐条标记"成真/落空"。**结算不可逆**；发现当初记错或要改判，只能追加一条更正记录，原记录保留。
3. 这条纪律是整个系统的诚实根基：没有先登记后结算，"复盘"就会沦为事后合理化。

## 六、校准与复盘

- 命中率自查：已结算预测中成真的比例；
- 信心分桶自查：把预测按概率分桶（如 50-70%、70-90%、90%+），看每桶的实际命中率是否匹配名义概率——"我说 80% 的事，真的八成发生吗"；
- **样本不足（<20 条已结算）时明说"样本不足，结论不可用"**，不拿小样本糊弄；
- 进阶（数据充足时）可计算 Brier 分数与 ECE：Brier = (1/n)Σ(p_i − o_i)²；ECE 按分桶加权 |置信度−命中率|。公式与分桶口径必须先定义再计算，不得事后挑口径。

校准结果不用于自动改写后续判断的概率（避免循环依赖与事后合理化），只用于向用户呈现"这套判断历史上靠不靠谱"。

## 七、决策台账

每个决定进台账：**推荐 → 行动 → 结果**，一步不落。复盘记录永久留痕：当时为什么这么定、后来怎么样了。台账格式见 `templates/decision-journal.md`。

## 八、商业计划生成（由证据生成 BP）

七章结构：执行摘要 · 市场机会 · 为什么是我们 · 关键假设与风险 · 计划与里程碑 · 什么会推翻这个计划 · 复盘与校准（模板 `templates/business-plan.md`）。

**每个数字必须有出处**（挂到假设清单或证据上）；数据不足的章节如实标注"数据不足"。这是一份"敢对投资人解释每一句话"的商业计划。
