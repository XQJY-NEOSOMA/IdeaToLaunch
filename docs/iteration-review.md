## 二、量化轨迹

- **selftest**：28 → 34 → 44 → 47 → 52 → 57 → 62 → 65 → 69 → 74（每条断言对应一处真实摩擦）；
- **验证器**：v1（6 项基线）→ v2（+C7 标签治理）；`verifier/runs/` 全程留痕（含失败与复跑）；
- **五轮盲测评分**：67 → 71 → 65 → 70/70 → 70/72（取低 68）；未过 80 门槛的根因从"组装器缺陷"收敛为"账本市场数据缺失"（正确否定）；
- **门禁正确行为 ×4**：BP 可读性拦截（R3）、不放行（R4）、数据错误识别（R5）、骨架 handoff 拒判（v3.7）。

## 三、核心结论

1. **真实使用驱动的迭代与文档驱动的迭代有本质区别**。R1–R7 的每一处修补都来自实战摩擦（豁免缺失、语义反转、数据矛盾、标签混用），而不是设计想象——冻结期"只按真实摩擦修补"的纪律被执行且有效。
2. **门禁体系的价值被真实证明**。四次拦截全部是"正确否定"：拦的是未签名放行、可读性不达标、无出处数字、未填写骨架——没有一次误伤。
3. **vendor 从死重变为可用资产**：v3.8 搬运时预测"≥60% 不会被调用"，R1/R4 中 gantt-chart-builder、workload-calculator、compliance-review-planner、process-doc、lp-proto-gen 被真实调用并暴露边界问题（均已入补丁）——该预测（0.75 先验）将于 2026-09-07 到期结算。
4. **诚实系统的终局可以是"机制全通 + 结论不放行"**：装甲项目环节 4.5 pass 而环节 4 fail，两者同时为真是系统健康的标志。
