# IdeaToLaunch 架构论证

> v1.0.0（2026-08-23）。前身：product-decision-router v0.1（纯路由），经所有者裁决升级为继承双引擎的旗舰技能。
> 依据：对 AIPD-OS（约 7.1 万行）与 Vencertia（约 3.3 万行）的全量逐行审查（9 个并行模块审查，关键结论经运行实证复核）。

## 一、定位：不是路由器，是全链路主管

IdeaToLaunch 是唯一入口技能，持有完整生命周期方法论：**想法 → 决策验证 → 产品落地 → 复盘回流**。Vencertia 与 AIPD-OS 从平级技能降级为它的**执行后端**——两个仓库保持独立（代码、数据库、版本线不变），但 agent -facing 的入口收敛到本技能一处。

## 二、三层职责

| 层 | 内容 | 驱动者 | 随模型变强？ |
|---|---|---|---|
| L0 主管层 | 本技能：意图判断、流程编排、方法论、升级决策纪律 | 模型 | ✅ |
| L1 引擎层 | vencertia CLI / aipd CLI（确定性执行后端） | 代码 | 能力稳定，不依赖模型 |
| L2 真相核 | 校准数学、证据权威门、预测台账、快照门禁、迁移、签名发布 | 确定性代码 | ❌ 不随模型漂移，严禁绕过 |

**为什么 L2 必须保留硬编码**：更强的模型不会涌现出正确的 Brier 分数或可验签的发布链；模型越强、产出越多，越需要不被模型左右的审计锚点（Vencertia ADR-002 / AIPD gate 体系均为这一原则的既有实现）。

## 三、为什么不合并底层仓库

跨仓实证：零代码重复、零互相引用、核心词汇同名异物、四处硬性合并障碍（Python 版本窗 / 依赖哲学 / 存储哲学 / 测试套件物理冲突）。加权决策矩阵：维持独立 4.40 vs SKILL 化 2.95 vs 合并 2.20（敏感性稳健）。全文见两仓各自的边界 ADR（AIPD `docs/architecture/project_boundary.md`；Vencertia `docs/adr/ADR-015`）。本技能是边界裁决中**唯一被允许的合成层**，仅通过文件级契约（`schemas/handoff_v1.json`）与两引擎交互。

## 四、僵化规则降级路线（审查实证清单）

两仓的僵化集中在编排层。以下硬编码点应降级为"默认模板 + 模型可偏离 + 偏离留痕"（不是删除）：

| # | 位置 | 现状 | 降级方向 | 优先级 |
|---|---|---|---|---|
| 1 | AIPD `supervisor/supervisor.py` PHASES（S0–S8） | 阶段机硬编码（多项目初始化还有静默丢失 bug） | 默认模板，模型可按项目增删阶段 | 高 |
| 2 | AIPD `experience/decision_card.py` | 选项影响按固定轮换表编造 | 模型基于项目事实生成；无事实标"数据不足" | 高 |
| 3 | AIPD `llm/experience.py` | "经验回灌"=3 条硬编码文本无差别注入 | 删除或改为按任务相关性检索 | 中 |
| 4 | Vencertia `capabilities/challenger.py` | solve 主链路"模型批判"是固定罐头文案 | 接真模型；无模型时诚实隐藏 | 高 |
| 5 | Vencertia `skills/biz.py` | BP 叙事由固定 prompt 模板约束 | 保留 source_claim_id 引用强制（真相守护），叙事放开 | 中 |
| 6 | 两仓发布/评测门禁中的恒绿 fixture | "评测通过"信息量≈0 | 门禁保留，混入至少一个 code-driven 行为契约 | 中 |

降级原则：**编排类规则**（顺序、呈现）交给模型；**真相类规则**（算数、记账、验签）永远保留。

## 五、路线图

- **v1.0（当前）**：旗舰技能 + 交接契约 v1（文件级，模型转述）；两仓 SKILL.md 废弃，本技能为唯一入口。
- **v1.1**：Vencertia `export-decision --format json` 与 AIPD `intake --from-handoff`（实现前先加 schema 校验测试）。
- **v1.2**：按第四节执行编排层降级（每项独立 PR + 回归测试）。
- 不计划：两仓合并、共享代码库、自动化状态互写。
