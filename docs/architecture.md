# IdeaToLaunch 架构与设计原则

> v3.2.0（2026-08-24）：内建确定性脚本工具箱。演进：v0.1 路由器 → v1.0 双引擎编排 → v2.0 独立运作 → v3.0 完全自包含 → v3.1 dogfood 实测修补 → **v3.2 计算后端内建（scripts/ 工具箱）**。

## 一、定位

IdeaToLaunch 是一个完全自包含的 Agent Skill：从一句话想法到产品发布的全链路主管。全部方法论、模板、交接契约内建，可脱离任何其他仓库或服务直接运行使用。

## 二、设计原则

1. **模型负责理解与编排，记录纪律守护真相与账本。** 意图判断、研究分析、内容生成由模型执行，模型能力增长直接提升全链路质量；诚实性不靠模型自觉，靠记录纪律：先登记后结算、结算不可逆、改判只追加、数字必须挂来源。
2. **环节间有阶段门。** 每个环节有出口判据，不满足不得进入下一环节；放行声明是证据门。
3. **诚实是一等约束。** 证据不足明说、数据不足标注、NO_GO/ABSTAIN 不得美化、不虚构任何现实世界事件。
4. **编排规则可裁剪，真相规则不可裁剪。** 生命周期阶段表、模板结构是默认模板，可按项目偏离（留痕）；记录纪律、证据分级、声明门不可偏离。

## 三、链路结构

六个环节（意图理解 / 机会验证 / 决策 / 产品落地 / 发布上市 / 运营复盘）构成闭环，环节间由阶段门与交接契约（handoff_v1.json）连接。详见 SKILL.md「全链路地图」与 `docs/chain-evaluation.md` 的环节覆盖评估。

## 四、文件组织

- `SKILL.md`：主管行为契约与全链路地图（agent 加载的唯一入口）
- `references/`：各环节方法论全本（执行时按需查阅）
- `templates/`：填入即用的交付模板
- `schemas/`：环节交接的机器可校验契约
- `scripts/`：确定性工具箱（计算/初始化/校验，纯标准库，自测覆盖）——诚实性纪律的机械化执行层
- `docs/`：本文件与全链路能力评估

## 五、演进路线

- v3.0（当前）：完全独立 + 全链路补全（市场研究/竞品/商业模式/发布增长/模板包）。
- 后续：按真实使用反馈迭代方法论细节；保持自包含原则——任何新增能力必须以文档/模板/契约形式内建，不得引入外部依赖。
